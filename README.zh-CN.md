# 🀄 德扑道场 (Poker Dojo)

> 好友开房、切磋成长。

德扑道场是一款面向好友对战的**服务端权威**在线德州扑克。所有游戏逻辑(洗牌、发牌、牌力评估、下注、结算)都在服务器执行,客户端只负责展示与传送操作。内置大厅、SNG 锦标赛、现金"训练赛"、完整多人引擎(真边池、多次发牌)、牌谱、生涯统计、聊天/表情/语音,以及 Capacitor 安卓薄壳。

> **健康游戏提示:** 本项目是供好友**练习娱乐的虚拟金币游戏**,**不是赌博**——无真钱下注、不可提现、无奖金。绿色竞技,远离赌博。

## ✨ 功能特性

- **服务端权威架构** —— 底牌用 `io.to(socketId)` 私发,广播只含公共信息,所有操作服务端校验;玩家爬自己的流量也看不到对手底牌,无法作弊。
- **可验证公平发牌** —— 每手重建整副牌,Fisher–Yates,无偏且不可预测。每一手都**在发牌前做出承诺、打完后揭示**,任何人都能离线重算整副牌、核对它中途没被换过（[怎么验](#-可验证公平)）。
- **两种房型**
  - **SNG(单桌锦标赛)**:盲注按时间递增、淘汰制、奖池抽水。
  - **现金 / "训练赛"(2–9 人)**:固定盲注,金币↔筹码带入/兑出(含价差抽水),训练时长 + 加时。
- **完整多人引擎** —— 正确的行动顺序(UTG 起手)、按钮轮转、**真边池**(相邻同资格档位合并 + 未跟注退还)。
- **多次发牌(run it N times)** —— 两人 all-in 时,落后方选发几次(1–5)、领先方同意,底池均分 N 份,在桌面上逐街依次发出。
- **牌谱 = 数据资产** —— 每手完整记录(各街动作、思考时间、底牌、公共牌、结果、时间戳),按玩家、按模式归档在 SQLite 中。每手另存一份完整原始记录,不会因表结构调整而丢字段。
- **生涯统计** —— VPIP / PFR / 3-bet / C-bet / AF / WTSD / 盈亏 + 盈亏曲线,从牌谱聚合。
- **牌桌体验** —— 环形座位、头像、呼吸行动框 + 环形倒计时、四色扑克、下注滑条、预操作、全押实时胜率%、筹码/底池动画、手机振动。
- **社交** —— 桌内聊天 + 快捷短语、点头像发表情、按住说话语音气泡。
- **账号与安全** —— 用户名/邮箱注册(邮件 6 位验证码),JWT 鉴权(每台服务器独立随机私章),生产环境 TLS/WSS。
- **安卓** —— **Capacitor** 薄壳指向线上站点;游戏更新只需部署服务器,无需重新发包。

## 🔒 可验证公平

洗牌一直是无偏的——每手重洗、Fisher–Yates、随机源用 CSPRNG。
但你**没有任何办法验证这一点**，只能选择相信我们。
现在每一手都在**发牌之前**做出承诺、打完之后揭示，你可以自己离线验算。

### 怎么做到的

1. **发牌之前**，服务器就把 `commit = SHA256(serverSeed)` 公布给全桌。
2. 整副牌的顺序完全由 `(serverSeed, clientSeed, nonce)` 决定性地算出来，没有别的随机源。
3. **整桌结束后**，服务器公布 `serverSeed` 与整副牌序，你可以从牌谱里取出来。

   为什么是整桌而不是每手：公开种子等于公开**整副牌**，连别人弃牌后从没亮过的底牌
   也一起公开了 —— 局间就放出去的话，等于给同桌每个人发了个免费 HUD。
   等到散桌并不损失什么：承诺在发牌前就已经公开了，晚点验一样算数。

因为承诺是在发牌**之前**公开的，服务器没法在看到任何人的牌之后再换一副牌——
换了的话，就和大家手上早就拿到的那个承诺对不上了。

### 自己验一手牌

1. **等本桌结束后**，在游戏里：**牌谱回顾 → 点开某一手 → 🔒 验证数据**，
   会把整份牌谱复制成 JSON，存成 `hand.json`。
   （牌桌还在进行中时种子不下发，按钮会当场告诉你。）
   （当前这手的承诺随时可以在**桌内菜单 ☰ → 🔒 公平性验证**里看到。）
2. 运行：

```bash
node PokerServer/tools/verify-hand.js hand.json
```

它检查三件事：

| # | 检查 | 为什么重要 |
|---|---|---|
| 1 | `SHA256(公布的种子)` 等于发牌前公布的那个承诺 | 服务器在看到任何一张牌之前就被锁死了 |
| 2 | 用公布的种子重新洗一遍，得到同样的牌序 | 这个牌序确实是那个种子算出来的 |
| 3 | 那副牌序能解释你当时**真的看到**的底牌与公共牌 | 这就是发到**你**手上的那副牌 |

验算器**不连服务器**，只用标准 SHA-256。整套方案不过几十行
（`PokerServer/src/games/poker/provably-fair.js`），你可以用任何语言重写一份来对答案。

想确认这个检查器不是在走过场？把 `community` 里任意一张牌改掉再跑一次——它会报错。

### 它证明了什么，没证明什么

- ✅ **证明了**：服务器没法在看到任何人的牌之后改变牌序。玩家真正担心的就是这件事。
- ⚠️ **没证明**：服务器不能在做出承诺**之前**反复试种子、挑一个对自己有利的。
  防这个需要玩家在**看到承诺之后**才确定 `clientSeed`。承诺现在已经提前一手公布，
  钩子留好了——但玩家自选 `clientSeed` 的入口还没做，目前 `clientSeed` 就是房间号。

> 一条实现上的说明，因为这是最容易做错的地方：种子随机源用的是**拒绝采样**，不是 `字节 % n`。
> 直接取模会让牌系统性地偏向前面几张。在 32 位下这个偏差约 1e-8 ——
> **小到任何统计测试都测不出来**，所以它只能从结构上解决，而不能靠「测一测」。

## 🧱 架构

```
浏览器 / 安卓 (薄客户端)  ──socket.io──►  Node 服务器 (权威)
   只负责展示 + 输入                        洗牌 · 发牌 · 判牌
                                            下注 · 边池 · 结算
                                            牌谱落库 (SQLite)
```

- **服务端权威**:规则全在服务器;客户端拿不到对手底牌。
- **牌力评估**:Cactus Kev + Paul Senzee 完美哈希。每张牌编码为 32 位整数;7 张枚举 C(7,5);分数 1(最强)…7462(最弱)。JS 版用 `>>> 0` 保持无符号 32 位运算。
- **存储**：SQLite 是用户、钱包流水、牌谱和比赛快照的持久化事实来源；内存负责实时计算，服务重启后从数据库恢复未结束牌局。`database.js` 继续提供兼容接口。

### 目录结构

| 路径 | 说明 |
|------|------|
| `PokerServer/` | Node.js 游戏服务器(Express + Socket.IO)与单页客户端(`index.html`) |
| `PokerLogic/`  | 牌力评估算法的 C# 原型(算法来源;JS 端为权威实现) |
| `mobile/`      | Capacitor 安卓薄壳(`capacitor.config.json` 指向线上地址) |
| `docs/`        | 设计文档 |

**技术栈:** Node.js · Express · Socket.IO · 原生 HTML/CSS/JS 客户端 · JWT · bcrypt · nodemailer · SQLite(better-sqlite3, WAL)。

## 🚀 本地快速开始

```bash
cd PokerServer
npm install
LOCAL_DEV=1 PORT=3000 node server.js
# 打开 http://127.0.0.1:3000
```

`LOCAL_DEV=1` 会绑定 localhost 并预置两个测试账号(`test`/`test`、`test2`/`test2`),可直接登录。未配置 SMTP 时,邮件验证码会回退打印到服务器日志。
