# 玩法扩展：短牌（6+ Hold'em）与奥马哈（PLO）—— 框架与计划

> 状态：**已完成并上生产**——第 0–3 期随 **2.0.0**（2026-11-19）上线，按玩法的新手引导随 **2.0.1**（同日）上线。下面保留计划原文和各期完成记录。
> 目标：建房时多一个「玩法」选项（德州 / 短牌 / 奥马哈），其余一切和现在一样。
> 最高优先级：**不给已经完善的德州引入任何新 bug**。整份计划围绕这一条排。

## 1. 两种玩法到底哪里不一样

| | 德州（现在） | 短牌 | 奥马哈 PLO |
|---|---|---|---|
| 牌堆 | 52 张 | **36 张**（去掉 2–5） | 52 张 |
| 每人底牌 | 2 张 | 2 张 | **4 张** |
| 怎么组牌 | 7 张里任选 5 张 | 7 张里任选 5 张 | **必须正好 2 张底牌 + 3 张公共牌** |
| 牌型大小 | 标准 | **同花 > 葫芦**；**A-6-7-8-9 算顺子**（最小的顺子）；其余和德州一样（顺子 > 三条，按赛事官方规则，见 §8.2） | 标准 |
| 下注上限 | 无限注 | 无限注 | **底池限注**：最多加到「跟注后的底池」 |
| 发牌流程、盲注、边池、多次发牌 | — | 不变 | 不变 |

结论：**短牌改的是「牌」**（牌堆 + 牌型），**奥马哈改的是「手」和「注」**（底牌张数 + 组牌规则 + 下注上限）。两者没有重叠，所以分两期做。

## 2. 排查结果：哪些地方写死了德州

完整清单（带行号）见同目录下 `INVENTORY.md`（2026-11-18 全库排查）。这里只列会**悄悄算错、不会报错**的几处 —— 它们是最危险的：

1. **`evaluate7Cards` 只看前 7 张**（`PokerLogic.js` 用固定的 21 种组合表）。奥马哈传进去 9 张，它就只算「公共牌 + 前两张底牌」，后两张被无声忽略。摊牌、多次发牌、胜率三处都在用它。
2. **`bestHandFrom` 是「任选 5 张」**。牌型提示、牌谱里的牌型名都用它。对奥马哈来说它给出的是德州的答案（比如手里四张同花，它会当成同花，实际上只能用两张）。
3. **Cactus Kev 查表认不出 A-6-7-8-9**。短牌里这手会被算成高牌（同花时算成普通同花），而它应该是顺子 / 同花顺。
4. **52 张牌的顺序在三处各写了一遍**：`Deck.reset()`、`equity.js`、`tools/verify-hand.js`（测试里还有两份）。可验证公平依赖三处**逐字节一致**，改漏一处，玩家离线验算就过不去。
5. **好几处用「底牌是不是 2 张」来判断「我有没有牌」**：客户端渲染（`myHoleCards.length === 2` 出现 4 次）、胜率计算（不是 2 张就直接丢掉）、亮牌（只收第 0 / 1 张）。奥马哈下这些会表现为「自己的牌不显示」「没有胜率」「预操作按钮不出现」。
6. **数据库 `mode` 列有约束**只许 `cash / sng`，玩法**不能塞进这一列**，要单独记。

## 3. 防回归：动手之前先把德州「钉死」

这是整份计划最重要的一节。思路：**先给现在的德州拍一张「标准答案快照」，之后每一步改动都必须一字不差地复现它。**

本项目有个现成的优势：**可验证公平让整副牌完全由种子决定**。给定种子 + 一串固定的行动，一手牌的全部结果（发了什么牌、谁赢、赢多少、牌型名、牌谱内容）就是确定的。所以可以做真正的「黄金样本」测试：

| 快照 | 内容 | 防的是什么 |
|---|---|---|
| **G1 牌力评估** | 用固定种子随机生成 20 万手 7 张牌，记下每手的分数 → 存一个哈希 | 评估器任何一点改动 |
| **G2 整手牌** | 用固定种子 + 固定脚本（各种行动组合：弃牌、全押、边池、多次发牌、straddle）跑 60 手真引擎，记下每手的牌谱（去掉时间戳）→ 存哈希 | 发牌顺序、结算、边池、牌谱字段 |
| **G3 离线验算** | 现有的真实牌谱 JSON 拿去跑 `verify-hand.js`，必须照样通过 | 可验证公平的牌堆顺序与发牌顺序 |
| **G4 胜率** | 剩余牌少时是穷举（结果确定），固定输入记下精确数值 | 胜率计算 |
| **G5 前端** | 现有的结构测试 + 截图脚本（README 那套）拍德州牌桌，和改之前逐张对比 | 渲染 |

**规矩**：G1–G4 在**第 0 期**（还没动任何代码时）用现在的代码生成、提交进仓库。之后任何一步只要让它们变了，就说明德州的行为被改了 —— 必须停下来查，不能「更新快照让测试变绿」。

另外：
- **老牌谱没有玩法字段 = 德州**。所有读牌谱的地方（回放、详情、分享、统计、验算器）都按这条兜底，历史数据一行都不用改。
- **德州那条路径只做「搬家」不做「改写」**：把现有函数原样挪进「德州玩法」里，调用方改成通过玩法层去调。搬完 G1–G4 全绿，才开始写新玩法。

### 3.3 奥马哈 4 张牌怎么摆（2026-11-19，用户：「两行或者都试一下，看哪个好用哪个」）

同一个摊牌画面换样式对比，量「有没有压到这个座位自己的名字 / 筹码、有没有压到别的座位、有没有出屏」，6 人 / 9 人 × 手机 / 小屏 / 电脑：

| 方案 | 结果 |
|---|---|
| 一排叠放（原来） | 不遮挡；但前三张只露出点数左半边，**花色完全看不见** |
| 两行 2×2（26px / 30px 两种大小） | 每张牌完整；但**每个座位都盖住了自己的名字和筹码**（全部尺寸、全部人数都如此） |
| 一排不叠、缩小到 24px | 不遮名字，但手机上靠边的座位**出屏** |
| **一排叠放 + 角标**（采用） | 点数 + 花色靠左竖排，正好落在露出来的那一条里；不遮挡、不出屏，每张都认得出 |

⚠️ 第一版只有被压住的前三张用角标、最后一张照常大字 —— 用户：「前三张小、最后一张大，很不协调」。改成**四张同一个样子、同一个字号**（取露出那一条放得下的最大值；「10」两位数单独收紧字距）。`plo.test.js` 守着不许再分开。

另修了一处：赢家高亮的牌带 `z-index: 2` + 抬起，会浮到最上层把后一张整个盖住（截图量到「第 2 张点不到」）；叠放时改回 `z-index: auto`，层次按先后。
自己的 4 张同样用角标（原来「10」被切成「1(」）。`plo.test.js` 守着：不许改成两行、高亮不许浮起来、角标靠左。

## 4. 框架：抽一层「玩法」

新目录 `src/games/poker/variants/`，每种玩法一个文件，统一接口：

```js
{
  id: 'nlhe' | 'shortdeck' | 'plo',
  deckRanks: ['2', …, 'A'],        // 短牌是 ['6', …, 'A']
  holeCount: 2 | 4,
  // 给定底牌和公共牌，算出这手牌的分数（越小越强，三种玩法都保持这条，比较代码不用改）
  score(hole, board) → number,
  // 最强组合：分数 + 用到了哪几张底牌、哪几张公共牌 + 牌型名（摊牌高亮、牌型提示、牌谱都用它）
  best(hole, board) → { score, holeIdx, boardIdx, category },
  betLimit: 'nl' | 'pl',
}
```

- **德州**：原样包住现在的 `evaluate7Cards` / `bestHand` / `handCategory`，一行逻辑不改。
- **短牌**：复用 Cactus Kev 的 5 张评估，在上面做一层**重新排序**：先认出 A-6-7-8-9（顺子 / 同花顺，排在同类最末），再把牌型档位换成短牌的顺序（同花提到葫芦前面，其余不变）。分数仍然是「越小越强」。
- **奥马哈**：底牌 6 种两张组合 × 公共牌 10 种三张组合 = 60 次 5 张评估，取最小。不需要新查表。
- 统一的 `freshDeck(variant)` 只写一处，`Deck.reset`、`equity.js`、`verify-hand.js` 都从它来（顺带消掉那三份重复的牌堆）。
- **下注上限**放在一个函数 `maxRaiseTo(game, player)` 里：无限注 = 全下额；底池限注 = 跟注后的底池。服务端校验和客户端（滑条、快捷按钮、数字键盘、快捷键 A）都读它，不各算各的。

玩法存在 `game.config.variant`，建房后**不可修改**（不像「带入审批」可以中途开关）。快照 / 重启恢复本来就原样保存 config，不用改。

## 5. 各处要改什么（按期）

### 第 1 期：玩法层 + 德州搬家（不改任何行为）
- 新建 `variants/`，德州实现 = 现有函数。
- 调用方改为经过玩法层：摊牌、多次发牌、胜率、牌型提示、牌谱牌型名、亮牌、发牌张数。
- 牌谱多记一个 `variant` 字段（德州写 `'nlhe'`）。
- **验收**：G1–G5 全部不变 + 全量测试 + 真服务器多桌跑一段 + 筹码守恒审计。**上生产观察几天**，确认德州无事再进第 2 期。

### 第 2 期：短牌
- 服务端：短牌评估（重新排序）、36 张牌堆、建房选项、牌谱 `variant: 'shortdeck'`。
- 可验证公平：`verify-hand.js` 按牌谱里的玩法建牌堆；加短牌的验算测试（真引擎打一手短牌 → 离线验算通过 → 改一张牌验算失败）。
- 胜率：36 张。
- 统计：个人数据按玩法分开（德州的 VPIP 不和短牌混）。
- 客户端：建房表单的玩法选项、房间卡片 / 比赛设置显示玩法、牌型速查表出短牌版、新手提示文案。
- **验收**：短牌专项测试（A-6-7-8-9 是顺子、同花大于葫芦、顺子大于三条）+ 第 1 期的快照仍不变 + 截图。

### 第 3 期：奥马哈
- 服务端：4 张底牌发牌、2+3 评估、底池限注（加注 / 下注上限校验 + 新的双语拒绝提示）、亮牌收 0–3。
- 可验证公平：发牌顺序按 4 张参数化。
- 胜率：4 张底牌；**性能要量**（每次评估是德州的 60 倍，翻前 4 人全押的蒙特卡洛会明显变慢，可能要降采样次数）。
- 客户端：所有「2 张」的地方改成按 `holeCount` 来（自己的牌、对手亮牌、对手小牌背、发牌动画、回放、牌谱详情、分享页）；4 张牌的座位布局要重新量（现在 30px × 2 刚好占满座位宽，4 张放不下，要叠放或缩小）；快捷键 A 在底池限注下改叫「最大」。
- **验收**：奥马哈专项（2+3 规则的反例：四张同花不算同花、公共牌四张同花加一张底牌不算同花）+ 快照不变 + 截图（9 人桌 4 张牌布局）。

## 7. 不做什么

- 不做短牌 + 奥马哈的组合（短牌奥马哈）。
- 不做有限注、Omaha Hi-Lo（高低分池）、5 张牌奥马哈。
- 不动数据库 `mode` 列；玩法先只记在牌谱 JSON 和 `config` 里，量大了再考虑加列。
- C# 原型（`PokerLogic/`）不跟着改（它本来就只是算法参考）。

## 8.1 原先的问题（留档）

1. **短牌里三条和顺子谁大？** 两种主流规则：
   - 三条 > 顺子（理由是短牌里顺子比三条更容易成；「多数平台这么定」是当时没查证的说法，查证后正好相反，见 §8.2）
   - 顺子 > 三条（和德州一样，更直观）
   - 或者做成建房时的选项（多一个开关）
2. **短牌的盲注结构**：沿用现在的大小盲（「其余和原来一样」），还是改成很多短牌局用的「只收前注 + 庄家盲」？建议先沿用大小盲。
3. **SNG 也开放这两种玩法，还是先只给现金桌？** 建议两种都开（建房表单两个页签都有这个选项，工作量差不多）。
4. **个人数据怎么展示**：生涯战绩默认只显示德州、加一个玩法筛选？还是默认合在一起？建议默认德州、可切换 —— 三种玩法的 VPIP 口径完全不同，合在一起没有意义。
