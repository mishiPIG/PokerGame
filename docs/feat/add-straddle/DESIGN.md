# 现金桌 UTG Straddle 设计

> 状态：已实现，待测试服验收
> 产品：德扑道场（Poker Dojo）  
> 更新时间：2026-07-25

## 实现记录

2026-07-25 已按本文档完成第一版实现：

- 现金桌创建与房主比赛设置支持开启/关闭 UTG Straddle；
- 预计下一手 UTG 完成当前手首次行动后，会收到 15 秒一次性选择提示；
- 服务端在开手时按最终阵容和筹码重新校验，固定收取完整 2BB；
- Straddle 生效后从 UTG+1 首先行动，UTG 保留最后行动权，最小加注按 2BB 重算；
- 公共桌面显示 `STR` 下注徽章，私人选择不会广播；
- 牌谱、详情和可视化回放已记录并还原 Straddle；
- 增加位置轮转、坐出过滤、两人禁用和固定时长的自动化测试；
- 已通过 `npm test`、服务端/页面脚本语法检查和本地启动冒烟测试，尚未部署测试服。

## 1. 背景

现金桌需要支持 Straddle，但不能在每手发牌前暂停 10～20 秒等待 UTG
作决定，否则会明显拖慢连续对局。

第一版采用“上一手期间预选下一手”的方式：服务器在当前手开始后预测下一手
UTG，但不在刚发牌时打扰玩家。该玩家完成当前手第一次行动、行动权移交给别人后，
才短暂展示一次选择；若再次轮到本人则立即隐藏并默认取消。始终没有安全时机时，
仅利用既有局间时间兜底展示，下一手开始前不再等待。

## 2. 目标

- 仅在房主允许的现金桌中提供 UTG Straddle；
- Straddle 固定为 2BB，是 live straddle；
- 下一手预计 UTG 在当前手进行期间提前决定；
- 选择界面只出现固定时间，不作为牌桌常驻按钮；
- 点击“下一局我要 Straddle”或“取消”后，界面立即消失；
- 超时未选择默认不 Straddle；
- 下一手发牌前不增加等待时间；
- 服务器在开手时重新校验位置、筹码和玩家状态；
- 牌谱完整记录 Straddle，供回放、统计和后续 AI 训练使用。

## 3. 非目标

第一版不包含：

- SNG Straddle；
- 两人桌 Button Straddle；
- Mississippi/Button Straddle；
- UTG+1 re-straddle 或连续 straddle；
- 玩家自定义 Straddle 倍数；
- 不足 2BB 时的部分/all-in Straddle；
- 永久“每次自动 Straddle”；
- 发牌前暂停并等待玩家选择；
- 房主强制某位玩家 Straddle；
- 第一手 Straddle。

## 4. 核心规则

### 4.1 生效条件

同时满足以下条件时才可以 Straddle：

1. 房间类型为 `cash`；
2. 房主已开启“允许 UTG Straddle（2BB）”；
3. 下一手最终有至少 3 名可参与玩家；
4. 玩家是下一手最终 UTG；
5. 玩家未坐出、未离座、仍在房间并有资格参加下一手；
6. 收取 Ante 后，玩家剩余筹码不少于完整的 2BB；
7. 玩家在上一手的有效选择窗口内明确选择 Straddle。

任一条件不满足，下一手均按“不 Straddle”处理，且不暂停发牌。

### 4.2 下注与行动顺序

以盲注 20/40 为例：

- SB 支付 20；
- BB 支付 40；
- UTG 支付 Straddle 80；
- 翻前由 UTG+1 首先行动；
- UTG 最后行动，并保留 check/raise 权；
- 翻前 `currentBet = 80`；
- 翻前最小加注到 160；
- 翻牌以后恢复正常规则，最小下注仍为原始 BB 40。

服务端实现上应把 Straddle 视为本手翻前的最大 live blind，而不是普通玩家行动。
因此 Straddle 不计为 VPIP 或 PFR。

### 4.3 Ante 与短筹码

强制下注顺序为：

1. 收取 Ante；
2. 收取 SB；
3. 收取 BB；
4. 收取 UTG Straddle。

UTG 在支付 Ante 后必须仍能完整支付 2BB，否则提前选择自动失效。第一版不允许
部分 Straddle，因为部分金额会导致最后行动权和最小加注语义不清晰。

## 5. 房主设置

### 5.1 创建房间

现金桌创建界面增加：

```text
允许 UTG Straddle（2BB）  [开关]
```

默认关闭。该字段存入现金桌配置：

```js
config: {
    // 现有字段……
    allowUtgStraddle: false
}
```

### 5.2 牌局期间修改

房主可在“比赛设置”中开启或关闭：

- 修改只影响尚未开始的下一手；
- 开启不影响当前手；
- 关闭时立即清除所有尚未生效的 Straddle 邀请和选择；
- 当前手已经收取的 Straddle 不可撤销；
- 设置变化向全桌广播；
- 房间信息中显示 `UTG Straddle 2BB` 标签。

建议广播文案：

```text
房主已开启 UTG Straddle（2BB），下一手起生效
房主已关闭 UTG Straddle
```

## 6. 提前选择交互

### 6.1 展示方式

选择界面不是常驻按钮，而是一条非阻塞、限时出现的轻提示，只向“预计下一手
UTG”私发并展示：

```text
下一手 UTG · Straddle 80？  是  否  15s
```

提示位于自己座位上方，采用无边框、无阴影、近透明深绿底和低饱和文字，不使用
橙色实心卡片。它不能遮挡底牌和主要行动按钮。玩家正在行动时绝不显示；
如果展示期间再次轮到本人，立即隐藏并按“不 Straddle”处理。

### 6.2 固定选择窗口

第一版安全选择窗口固定为 **15 秒**：

- 当前手开始时仅创建服务端候选状态，不显示界面、不开始倒计时；
- 候选玩家完成当前手第一次有效行动、行动权移交后才显示并开始 15 秒倒计时；
- 如果该玩家弃牌，此时也是最理想的展示时机；
- 玩家点击任一选项后立即结束窗口并隐藏提示卡；
- 15 秒内未选择，自动隐藏并记为“不 Straddle”；
- 展示期间再次轮到该玩家，立即隐藏并记为“不 Straddle”；
- 若当前手结束前从未出现安全窗口，则在既有 5 秒局间内兜底展示 4.5 秒；
- 局间兜底不会延长或重置下一手的开局计时；
- 下一手绝不为等待选择而延迟。

时间是产品常量，不由房主或玩家配置：

```js
const STRADDLE_DECISION_MS = 15_000;
const STRADDLE_INTERMISSION_MS = 4_500;
```

### 6.3 两个按钮的语义

“下一局我要 Straddle”：

- 提交一次性同意；
- 服务端确认收到后提示卡立即消失；
- 可短暂显示 Toast：`已选择：下一局 Straddle 80`；
- 只对紧接着的下一手有效。

“取消”：

- 提交明确拒绝；
- 点击后提示卡立即消失；
- 本手余下时间不再显示，也不能重新打开；
- 下一手默认不 Straddle。

超时与“取消”的游戏结果相同，但服务端保留不同原因，便于排查交互问题：

```text
accepted | declined | expired | invalidated
```

## 7. 下一手 UTG 的预测与最终校验

### 7.1 预测

当前手按钮位已确定后，服务器根据现有可参与玩家推算：

1. 下一手按钮位；
2. 下一手 SB、BB；
3. 下一手 UTG；
4. UTG 是否有足够筹码支付预计 Ante 和 2BB。

只有预测满足条件时，才向该玩家发送选择邀请。客户端不能自行计算或声明自己是
下一手 UTG。

### 7.2 阵容变化

选择窗口期间或窗口结束后可能发生：

- 玩家站起、留座离开、坐出或退出房间；
- 玩家掉线；
- 玩家在当前手输掉筹码，下一手不足 2BB；
- 其他玩家入座、补码或恢复参与；
- 房主关闭 Straddle；
- 房间暂停或结束。

因此预测不是最终授权。`startHand()` 必须按最终可参与阵容重新计算 UTG：

- 最终 UTG 与接受邀请的玩家相同，且全部条件仍满足：执行 Straddle；
- 最终 UTG 已变化：原选择失效，新 UTG 默认不 Straddle；
- 玩家筹码或状态不再满足：原选择失效；
- 不向新的 UTG 临时弹窗，也不等待其选择。

选择失效时可向原玩家私发：

```text
因座位或筹码状态变化，下一局 Straddle 已取消
```

### 7.3 掉线与重连

- 选择结果以服务器为准，不依赖客户端本地状态；
- 玩家选择后短暂掉线并重连，只要最终仍能参与且仍是 UTG，选择继续有效；
- 玩家尚未选择就掉线，窗口计时继续，不暂停；
- 重连时窗口仍有效则恢复剩余时间，已超时则不再显示；
- 掉线导致玩家下一手不可参与时，选择作废。

## 8. 第一手规则

房间第一手没有上一手可用于提前选择，因此第一版第一手不允许 Straddle。

从第一手开始后，服务器才为第二手预计 UTG 创建选择窗口。这样无需在房主点击
“开始”后增加等待，也避免等待阶段玩家频繁入座导致 UTG 不稳定。

## 9. 服务端状态

房间增加临时状态：

```js
game.straddleDecision = {
    sourceHandId: "当前手唯一标识",
    targetHandSeq: 12,
    candidateUserId: "预计下一手 UTG",
    candidateSeat: 3,
    amount: 80,
    status: "pending", // pending | accepted | declined | expired | invalidated
    offeredAt: null, // 完成首次行动、真正展示时再写入
    deadlineAt: null
}
```

约束：

- 一个房间最多存在一个待生效选择；
- `targetHandSeq` 防止旧 Socket 消息作用于错误手牌；
- 玩家事件必须包含目标手牌序号，服务端校验用户、期限和状态；
- 客户端只能接受或拒绝，不能提交金额、位置或用户名；
- 当前手结束、房主关闭功能或候选资格变化时清理/失效；
- 下一手完成校验和收取后立即清除，不能跨手复用。

建议 Socket 事件：

```text
服务器 → 玩家：straddle_offer
玩家 → 服务器：straddle_decision
服务器 → 玩家：straddle_decision_result
服务器 → 全桌：straddle_posted
```

请求示例：

```js
socket.emit('straddle_decision', {
    roomId,
    targetHandSeq,
    accept: true
});
```

## 10. 开手处理顺序

`startHand()` 的相关顺序应为：

1. 确定最终可参与玩家；
2. 轮转并确定按钮位；
3. 确定 SB、BB、UTG；
4. 初始化本手玩家状态；
5. 收取 Ante；
6. 收取 SB 和 BB；
7. 校验上一手的 Straddle 选择；
8. 若有效，收取完整 2BB Straddle；
9. 发底牌并创建牌谱；
10. Straddle 生效时从 UTG+1 开始翻前行动，否则按原规则从 UTG 开始；
11. 开启正常行动计时器并广播状态；
12. 为再下一手创建候选状态，等待该玩家完成首次行动后再展示。

注意：实际代码中 Ante 和盲注的初始化顺序可以为保持现有结构做等价调整，但筹码
资格判断和牌谱结果必须符合本文语义。

## 11. 公共状态与展示

Straddle 真正生效后，全桌可见：

- UTG 座位上方显示 `STR 80` 筹码徽章；
- 桌面消息：`张三 UTG Straddle 80`；
- 翻前当前注额和最小加注按 80 计算；
- 状态中提供本手 Straddle 玩家和金额。

广播的 `game_state` 可增加：

```js
straddle: {
    type: "utg",
    userId: "...",
    amount: 80
}
```

未生效前的选择属于玩家私有意图，不向其他玩家广播；只有实际收取后才公开。

## 12. 牌谱与统计

牌谱顶层增加：

```js
straddle: {
    type: "utg",
    userId: "...",
    amount: 80
}
```

并在强制下注/行动记录中记录：

```js
{
    userId: "...",
    street: "preflop",
    action: "straddle",
    amount: 80,
    thinkMs: 0
}
```

回放应在盲注之后显示 `UTG Straddle 80`，并从 UTG+1 开始回放翻前行动。

统计规则：

- Straddle 不计 VPIP；
- Straddle 不计 PFR 或 3-bet；
- 玩家随后主动 call/raise 时再按正常规则计入统计；
- 后续可独立增加 Straddle 次数、频率和 Straddle 底池盈亏。

## 13. 安全与一致性

- 位置、金额、期限和资格全部由服务器权威判断；
- 客户端不能给其他玩家选择；
- 重复提交只接受第一次有效决定；
- 截止时间使用服务器时间；
- 过期 Socket 消息不能影响后续手牌；
- Straddle 扣款必须只执行一次；
- 广播状态不得泄露尚未生效的私人选择；
- 房间解散、比赛结束和内存清理时必须清理决定计时器。

## 14. 验收场景

至少覆盖：

1. 房主关闭时，全桌永不出现选择；
2. 三人及以上、功能开启时，仅预计下一手 UTG 收到邀请；
3. 点击 Straddle 后提示卡立即消失，下一手正确扣除 2BB；
4. 点击取消后提示卡立即消失，本手不再出现，下一手不 Straddle；
5. 15 秒未选择自动消失，下一手不 Straddle；
6. 刚发牌和玩家当前行动时不显示选择卡；
7. 候选人完成首次行动、轮到别人后才显示；
8. 展示期间再次轮到候选人，立即隐藏并默认取消；
9. 当前手始终无安全窗口时，仅在局间展示 4.5 秒且不延迟下一手；
10. 第一手不 Straddle，第一手期间可预选第二手；
11. Straddle 后从 UTG+1 首先行动，UTG 最后行动；
12. 20/40 桌 Straddle 80，最小加注到 160；
13. 收 Ante 后不足 2BB，选择失效且不部分扣款；
14. 候选人选择后站起/坐出，选择失效；
15. 阵容变化导致最终 UTG 改变，原选择失效，新 UTG 不被临时等待；
16. 已选择后掉线重连，若资格和位置未变则选择仍有效；
17. 房主关闭功能后，待生效选择立即清除；
18. 两人桌不出现 UTG Straddle；
19. 牌谱、回放和公共状态正确记录 Straddle；
20. Straddle 不误计入 VPIP/PFR/3-bet；
21. 重复、过期或伪造的选择事件不能重复扣款或作用于其他手牌。

## 15. 待产品确认
